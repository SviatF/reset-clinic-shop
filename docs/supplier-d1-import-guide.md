# Перенесення 114 нових товарів у Cloudflare D1

GitHub commit з товарами створює лише джерело імпорту; він сам по собі **не змінює D1**.

## Для власника магазину

1. На Worker `reset-clinic-shop` має бути прив'язка `SHOP_DB` до бази `38a072d9-bb85-4417-bf92-4f0652cc4056`. У ній повинні бути таблиця `shop_documents` і п'ять уже ініціалізованих документів: products, categories, brands, orders, activity. Не створюйте порожні замінники поверх чинних замовлень.
2. Для тестового середовища встановіть `SHOP_STAGING=true`, `SHOP_STORAGE_BACKEND=cloudflare`, `SHOP_PRODUCTS_BACKEND=d1`. Не перемикайте production до повної міграції поточних замовлень і каталогу.
3. Розгорніть останній `main` через Cloudflare Builds. Деплой GitHub Actions вимагає `CLOUDFLARE_API_TOKEN` та `CLOUDFLARE_ACCOUNT_ID`, наразі їхня наявність не підтверджена.
4. Увійдіть у `/admin/products`; у блоці «ІМПОРТ ПОСТАЧАЛЬНИКІВ · D1» відобразиться кількість відсутніх чернеток із 114. Натисніть «Зробити резервну копію та перенести …». Збережіть резервну копію **поза GitHub**; вона містить персональні дані з замовлень.
5. Перевірте `GET /api/admin/supplier-draft-import` під авторизованою сесією. Успіх означає `missing: 0`; це підтверджує наявність 114 записів у вибраній D1. Не плутайте це з перевіркою їхніх цін/залишків/фотографій.

## Гарантії нового endpoint

- POST доступний лише авторизованому адміністратору в staging D1 з підтвердженням; перевіряється той самий Origin.
- Імпортує **тільки 114 записів** із `data/supplier-import-2026-11-11.json` та `data/products.json`.
- Повторний запуск не дублює позиції (звірка `slug` та `id`) і не перезаписує існуючі товари, ціни, залишки чи замовлення.
- Записує лише статус `draft`, `stock_quantity=0`, `track_stock=true`. Публікацію потрібно виконувати вручну після перевірки асортименту.
- Якщо D1 не готова, імпорт не запускається; відсутній документ не замінюється порожнім списком.

## API

`GET /api/admin/supplier-draft-import`: статус, джерельні 114 позицій, число відсутніх у D1.

`POST /api/admin/supplier-draft-import`: same-origin, admin cookie, JSON `{"confirm":"IMPORT_114_SUPPLIER_DRAFTS"}`. Для захисту від випадкового імпорту використовуйте кнопку в адмінпанелі, яка перед запитом завантажує резервну копію.

**Обмеження:** у цьому кроці змінений тільки код GitHub. Без авторизованого доступу до Cloudflare та успішного деплою неможливо чесно підтвердити, що дані фізично записані в D1.
